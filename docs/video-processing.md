# Video Processing

`backend/clipper/media.py` owns source probing, ingest, audio extraction, subtitle/ASS rendering and FFmpeg export. `backend/clipper/subtitles.py` handles SRT/VTT, cue fingerprints, word grouping, presets, and translation validation. FFmpeg/ffprobe are runtime binaries; Klipnara does not bundle them.

## Ingest and source validation

- File upload accepts `.mp4`/`.mov`, rejects empty files, enforces default 2 GiB cap (`CLIPPER_MAX_UPLOAD_BYTES`) and checks for at least 1 GiB free before writes.
- `probe()` accepts FFmpeg-recognized MP4/MOV formats, requires a video stream, allows audio to be absent, and validates positive duration up to 4 hours plus positive dimensions. AI Smart Clip needs audio only when it must create a transcript; Quick Clip does not.
- Direct URL import accepts HTTPS on port 443 only. It expects a direct media response (video MIME type or `application/octet-stream`), not a site page; YouTube/youtu.be/youtube-nocookie hosts are rejected before DNS or network access. It allows at most three redirects, revalidates each target, resolves public addresses and pins TLS connection to the resolved address to reduce DNS-rebinding/private-network risk.
- Source files are hashed during ingest. Database stores metadata and path; local file is retained until source deletion.

## V2.7 shared Asset Library and Pexels import

Video remains in canonical `sources` storage and receives a corresponding `library_assets` metadata row; Quick Clip and existing source routes still use same source ID/file. Images/audio are stored once under `SOURCE_DIR/library-assets`. Local uploads are streamed to a scoped `.part` file, size/free-space capped, ffprobe-validated, SHA-256 hashed, and deduplicated against same-kind library media before registration. Existing Source Library video upload retains `CLIPPER_MAX_UPLOAD_BYTES` (2 GiB default); direct Asset Library/Mood video uploads cap at 512 MiB, image at 25 MiB, and audio at 100 MiB. Pexels imports cap at 512 MiB. Mood references shared media by ID through `mood_assets`; detaching Mood link or deleting its draft does not remove shared file. Legacy Mood project uploads remain readable and project-scoped; no bulk migration runs.

Optional Pexels search calls official `https://api.pexels.com/v1/videos/search` with backend-only `PEXELS_API_KEY`; response JSON is capped at 4 MiB and search-result cache holds at most 100 entries for five minutes. Browser requests are user-triggered. Import re-fetches selected metadata/file ID, accepts only selected MP4 from allowlisted HTTPS media hosts on port 443, resolves public IPs and pins TLS connection for each redirect, accepts at most three redirects, enforces content type and 512 MiB byte cap, checks at least 1 GiB free, probes/hashes downloaded file, then registers ordinary source and library metadata transactionally. Hash-identical local video is reused without another stored copy. Separate single-thread executor runs one Pexels import at a time. Cancel/retry/status are persisted in `asset_import_jobs`; startup marks interrupted jobs failed, removes scoped temporary output, and removes an orphan final only when hard-link identity proves job ownership. No source is copied for Mood or automatically analyzed/rendered. Provider/license citations are stored for user review; legal rights are not verified.

Asset deletion checks active source jobs and Mood references before removing shared video/source rows and linked renders. Deleting a source through legacy source route also removes its library metadata, while active job or Mood references block deletion. Missing tracked files can be removed safely without deleting paths outside managed roots. Local image/audio deletion similarly rejects Mood references.

## YouTube Clip preview and optional segment import

YouTube Clip URL parsing is separate from `/api/sources/url`. Supported standard forms are `youtube.com/watch?v=VIDEO_ID`, `www.youtube.com/watch?v=VIDEO_ID`, `m.youtube.com/watch?v=VIDEO_ID`, `youtu.be/VIDEO_ID`, and `youtube.com/shorts/VIDEO_ID`. Exact hostname and 11-character video ID checks reject lookalike hosts, userinfo, ports, unsupported paths, and malformed IDs. Valid `t`/`start` is interpreted as timestamp; output canonical URL drops tracking parameters. No user-controlled hostname is fetched by the metadata route.

The browser's official YouTube IFrame Player API loads preview directly from YouTube. Optional server-side `YOUTUBE_DATA_API_KEY` uses official `videos.list` metadata (`title`, `channel`, thumbnail, duration, embeddable status) over fixed Google HTTPS endpoint; timeout is 8 seconds, response cap 256 KiB. Missing key, quota/API/network error or unavailable metadata leaves preview attempt available. Metadata is transient. No media bytes pass through the iframe into FFmpeg.

Adapter is optional and disabled by default. To enable, set `YOUTUBE_IMPORT_ENABLED=1`, install external `yt-dlp` (`YT_DLP_PATH`) plus FFmpeg/ffprobe. It is not official YouTube tooling; a local rights checkbox is an attestation, not legal/platform permission verification. Platform terms may disallow a method even for content user owns. Do not use browser cookies, session credentials, authenticated config, DRM bypass, or access-control workarounds; adapter passes `--ignore-config` and only canonical YouTube URL.

The worker passes selected times to yt-dlp `--download-sections`, `--no-playlist`, argv-only `subprocess.Popen(shell=False)`, and FFmpeg remux/cut options. This requests partial-section transfer; server/format may require extra bytes or reject the request. The worker caps temporary output at `CLIPPER_MAX_UPLOAD_BYTES` (default 2 GiB), selected end at four hours, checks at least 1 GiB free space, requires exactly one ffprobe-valid MP4/MOV video of 1 second–4 hours, hashes it, and stores it as a managed `sources` row. Source is then passed to existing Quick Clip endpoint and render queue; no parallel rendering pipeline. Import statuses are persisted in additive `youtube_import_jobs`; cancellation signals downloader process group and removes that job's temporary folder. Interrupted jobs fail retryably and scoped temp/orphan files are cleaned on startup. Successful sources are not removed by retries or clip cleanup.

When adapter is disabled, unavailable, blocked, unsupported, or unsuitable, Source Library/upload fallback remains. No video is guaranteed importable. Unknown/private/age/geo/format/access restrictions are not bypassed. Direct URL media ingest continues rejecting YouTube page hosts before DNS/network access.

## Transcription audio extraction

On a cache miss, job worker runs FFmpeg with `loudnorm=I=-20:TP=-1.5:LRA=11`, mono, 16 kHz, signed 16-bit PCM WAV. `whisper.cpp` emits JSON timestamps; WAV and Whisper JSON work files are deleted after use. Transcript itself is stored in SQLite for later edits/renders.

Legacy synchronous `subtitles/auto-generate` remains separate from source transcription and processes the saved trim or selected scene. The editor queues the full ordered composition: FFmpeg extracts source intervals with transition-aware output timing, applies per-interval loudness normalization, uses midpoint cuts or overlap `acrossfade`, and inserts silence between Insert Slots before resampling to mono 16 kHz. Local Whisper receives temporary PCM WAV and returns segment timing. Gemini `gemini-3.5-transcribe` receives temporary AAC/M4A after consent, requests verbatim word timestamps/speaker labels, and is capped at 30 minutes. OpenAI `gpt-transcribe` receives temporary AAC/M4A after consent (25 MiB cap) and returns transcript text only; timing is never inferred. Local audio is deleted after success/failure; Gemini upload is deleted after its request when possible. Manual/import mode needs no audio or STT setup.

## Render pipeline

`render()` creates `{clip_id}-{job_id}.mp4` under `CLIPPER_CLIP_DIR` (default local `clips`). Multi-Scene output duration is ordered scene time plus Insert Slot frame counts minus Overlap frame counts. Renderer scales to fill portrait, applies center/manual crop percentages, optionally burns ASS subtitles, maps video/audio, writes H.264 + AAC, `yuv420p`, and `+faststart` MP4. Clip/source-time cues are clipped at scene ownership boundaries and remapped to output time; inserted slots contain no source-timed cues. Explicit output-time cues may occupy a slot. Output-time tracks are used only when source hash and composition fingerprint match. Quick Clip defaults to subtitles Off. ASS supports sentence/phrase/word/karaoke cue modes, presets, font/color/outline/highlight, background, alignment, animation, safe margin, and width. For a source without audio, renderer adds finite-duration silent stereo AAC through FFmpeg `anullsrc`; source file is not modified.

Word Pop is independent of preset/style state. Before render, backend requires every current visible cue to have explicitly reviewed word alignment whose normalized word text reconstructs cue text and whose finite intervals stay inside cue bounds without overlap; gaps are valid. Gemini word annotations are grouped without inventing timings. Manual edits preserve cue text/words and clear review when text or cue timing changes; segment-only and text-only providers cannot supply Word Pop timing. Scene mapping clips each word interval to its source scene and assigns cumulative output time; repeated source words remain repeated events, while a word split across adjacent scene cuts is rejoined when source identity and boundaries match. ASS writes one `Dialogue` event per output word, centered at selected vertical position, with safe-width fitting and per-word Pop/Scale/Fade/None transforms. ASS timestamps resolve to centiseconds (10 ms); intervals that quantize to zero fail closed. Preview uses the same mapped word timing and controls, but browser frame cadence/font metrics can differ; compare Preview with MP4 manually.

### V2.9 Batch Creator renders

Batch Creator stores up to 10 timestamp-based source clips or Mood Quotes draft items in `video_batches` and `video_batch_items`. Source files and shared Mood assets are referenced, not copied. Each batch schedules one render child at a time through the existing FIFO worker; child jobs snapshot clip edit JSON or Mood quote/composition plus asset hashes, then use the existing renderers and output paths. Pause holds unclaimed items and waits for an active render; resume continues pending items, cancel preserves completed outputs, and retry creates a new child job. Startup recovery pauses interrupted batches and leaves failed items retryable. Every output remains independently reviewable/downloadable; no publication is enqueued. These V2.9 paths and the added regression script have not been run in this checkout.

### V2.6 Multi-Scene, Scene Transitions, and Cut Range renderer

Clip scene edits, `transitions`, and Cut Range fragments stay in `clips.edit_json`; render jobs snapshot the full edit in `jobs.options_json`. A transition belongs to one ordered pair, keyed as `fromId>toId`; legacy missing `timing_mode` means `overlap`, missing/orphan keys are ignored or reconciled, and projects without transitions remain hard cuts. The editor creates new joins as 0.5-second Insert Slots; API clients omitting `timing_mode` retain legacy Overlap behavior. Source ranges remain non-destructive. Renderer emits complete selected source frames (floor of interval × FPS); sub-frame source tails remain stored but do not render. Output positions derive from source ranges and integer frame counts; a shared frame-tick accumulator avoids cumulative float drift. Insert Slot adds its frame duration; Overlap subtracts it. Positive transition durations round half-up to nearest frame in both frontend and backend. If per-boundary rounding makes cumulative Overlap exceed scene frame budget while raw durations fit, shorten outgoing overlap frames first, then incoming, identically in frontend/backend. Render/API reject non-positive, non-finite, unsupported, non-adjacent, or scene-overflowing timing. New transitions are constrained to 0.1–2 seconds; older longer/shorter valid transitions remain readable and renderable until timing is edited. `POST /render`, subtitle import/transcription, audio fades, titles, and output-time subtitle validation use resulting composition duration.

For Multi-Scene, FFmpeg opens each selected source interval, resets timestamps, scales/crops to portrait, normalizes VFR/CFR video to requested FPS, dimensions, pixel format and timebase, and normalizes audio to stereo 48 kHz. Overlap Crossfade uses `xfade=fade`; Overlap Dip to Black uses `xfade=fadeblack`. Directional Wipe, Slide, and Smooth, Circle Open/Close, Dissolve, Pixelize, Radial, and Fade to White map to their named FFmpeg `xfade` transitions in both timing modes. Insert Slot never borrows footage outside selected ranges: it holds the last selected frame and first selected frame for exactly the slot's frame count, blending those holds with the selected `xfade` transition; Dip to Black fades the two holds to/from black then concatenates them. Hard cuts concatenate. Multi-boundary offsets accumulate prior insert/overlap frame counts. Legacy Zoom Blur is accepted only as Overlap and maps to Crossfade; it is not offered for new edits. Smooth Audio Transition on Overlap uses `acrossfade`; unchecked audio hard-switches at overlap midpoint. Insert Slots add matching silence to audio; Smooth Audio fades scene audio down before the slot and up after it, without repeating source samples. Missing source audio remains silence. Global audio filters apply after composition.

Source-timed captions and Word Pop are assigned to one scene at the same Overlap midpoint; Insert Slots shift following scene cues and contain no source-time cue duplication. Explicit output-time cues remain on their chosen output seconds and become stale when composition timing changes. Cues crossing scene boundaries are clipped to ownership; word times are clipped with the cue, not invented. Subtitle composition fingerprints include output offsets and transition mode/duration. Review alignment when edits leave timed words stale.

The browser preview uses two synchronized video elements during active transitions; the second decoder stays paused outside transitions. Overlap preview seeks both source clocks; Insert preview freezes each selected endpoint and advances the slot on a composition clock. CSS opacity approximates FFmpeg transition frame blending; Dip to Black and audio envelopes may differ by browser cadence. Compare each slot, play-through, seek, output duration, audio, and subtitle timing in Live Preview and final MP4 manually. Source seek latency depends on browser/container. Cut Range stays in output seconds; Overlap is divided between adjacent scenes at its midpoint before source ranges are split, while ripple deletion shortens/deletes intersected Insert Slots. Split carries an existing transition only to the split continuation; reorder/delete never silently attach a transition to a new pair. New joins remain hard cuts until explicitly added. Draft output may exceed 180 seconds; editor and Batch Creator final renders reject output over 180 seconds, while initial Quick Clip creation retains existing duration behavior. Scene caps remain 12 scenes and 0.5 seconds per retained interval; smaller fragments fail instead of disappearing silently. Final file is checked with ffprobe for H.264/AAC, requested dimensions, and duration within 0.3 seconds. 720p uses x264 CRF; 1080p uses AMF bitrate quality when encoder exists, otherwise x264 CRF fallback. CPU cost grows with scene count because every interval is decoded/re-encoded. Transition render and preview synchronization checks remain unrun in this checkout.

Transition filters follow FFmpeg's [official filter reference](https://ffmpeg.org/ffmpeg-filters.html) (`xfade`, `fade`, `tpad`, `concat`, audio fades/crossfades). No runtime FFmpeg validation was run for this transition-slot change.

### Mood Quotes compositor

`mood_renderer.py` writes temporary ASS/gradient assets and streams one background plus optional music through FFmpeg; it never stores video frames in Python memory. Background can be shared-library or legacy project-owned still, generated solid/gradient, or shared/Source Library video. A selected segment starts at `video_start`; video loops when requested, otherwise `tpad=clone` holds its last frame. Active background audio and selected music are resampled to stereo 48 kHz before mixing. Music supports trim, start offset, mute, volume, sample-loop, fades, and `amix`/`alimiter`; FFmpeg delays the music stream by the composition offset and places fades on that output timeline. Server validates audible span/fade bounds against asset duration. Muted/zero-volume selections intentionally allow silent AAC; active selected audio is signal-checked before render and output audio is checked when an active source has signal. Silent/corrupt active audio fails with actionable error. No music means background audio or silent AAC.

Single Text uses one positioned ASS quote and preserves legacy timing. Sequential Text uses ordered timed segments with per-segment fade/fade-up/slide/scale animation. Validated provider segments are reused when they fit; otherwise deterministic local sentence/clause segmentation and word-weighted timing run. Short discourse openers merge with following clauses; unsafe connector boundaries are avoided. Text layout is preflighted against the safe frame. ASS typography includes preset/user font weight, color, outline, shadow and animation. Text is escaped into ASS, never shell-concatenated. Bounded values, validated colors, project-owned asset IDs, and argv-based FFmpeg calls constrain inputs. Output metadata is stripped. ASS/gradient/log files and failed partial MP4 are removed on success/failure/cancel; startup cleans interrupted-render artifacts. A hard kill between render and DB update can leave an orphan final file.

`composition.visual` drives the existing renderer, not a parallel pipeline. Background is scaled-to-fill and cropped to 9:16 first. User-selected still/video backgrounds may then use bounded `zoompan` (4/8/12% maximum zoom for Subtle/Normal/Strong) for slow zoom, pan, or Ken Burns. Crop stays within the filled frame, so no black bars; zoom can soften low-resolution source detail. Color controls map to `eq` and `colorbalance`; atmosphere uses `vignette`, optional low-strength `noise`, `drawbox`, and one generated RGBA gradient overlay. Text backing remains separate. Effects are chained in one video filtergraph with existing ASS overlay and audio graph. There is no GPU-only filter or added video dependency; software effects can increase CPU time, especially grain/1080p. A missing FFmpeg filter returns an actionable unsupported-filter error. Soft glow is not implemented. Output encoder selection and audio mix contract remain unchanged.

Mood composition defaults: 720×1280, 30 FPS, 5–40 seconds; 1080×1920 is optional. 720 uses `libx264 veryfast CRF 23`; 1080 uses `h264_amf` on builds that provide it, otherwise CPU x264 fallback. Render progress comes from FFmpeg `out_time_us`. Previous render paths stay intact until a replacement succeeds. Approved render hash is stored separately in `mood_renders`; any composition/quote edit invalidates review without deleting the old file. Timeline selection, zoom, and snap are UI-only; segment/background/music edits remain composition fields, and render jobs retain immutable quote/composition snapshots.

Mood fonts use Windows system families Arial, Georgia, Segoe UI, Tahoma, Trebuchet MS, and Times New Roman. Klipnara does not bundle or download fonts. Preview uses matching system font names and FFmpeg/libass resolves installed system fonts; fallback depends on installed OS fonts. No third-party font redistribution occurs. Text layout is preflighted against output frame and returns a clear validation error if it cannot fit.

Step 3 Live Preview uses CSS transforms/filters and the same saved effect values; no FFmpeg or AI request runs per edit. Image/video background motion is simulated from the still image or cached video thumbnail. Thumbnail API seeks requested frame, scales to at most 720×1280, and caches JPEG per asset/0.1-second frame in its project `previews` folder. Frontend debounces frame changes and ignores stale loads; server retains at most 12 recent frames per video. The timeline playhead synchronizes local music preview offset, trim, loop, fades, and mute. Preview Penuh plays actual background video/audio and music with the same composition timing. CSS temperature/grain/vignette and browser typography are approximations; FFmpeg/libass output can differ. Compare editor, Preview Penuh, and MP4 final. Safe Area is editor-only.

| Requested output | Video encoder in current code | Audio |
|---|---|---|
| 720 × 1280 | `libx264`, `veryfast`, CRF 23 | AAC 128 kbps |
| 1080 × 1920 | `h264_amf` balanced VBR when listed (quality bitrate: 2.5/4/6.5 Mbps); otherwise `libx264 veryfast` CRF 28/23/19 | AAC 128 kbps, stereo 48 kHz |

V2.6 source-clip renderer falls back to x264 when the FFmpeg build does not list `h264_amf`; an AMF encoder that is listed but fails at runtime does not automatically retry with x264. Mood Quotes retains its own AMF-when-available/fallback selection. 720p stays CPU x264 by measured quality/speed tradeoff. Source-clip crop is center/manual only; no face tracking. V2.8 subtitle tracks can have word timing from Gemini; local Whisper remains segment-timed and OpenAI `gpt-transcribe` is text-only. No timestamp precision or provider quality is guaranteed. Historical benchmark rows predate V2.6/V2.8 and are not measurements of these changes.

FFmpeg reports `out_time_us` for progress. A cancelled/failed render removes partial new output and preserves previous render path; successful replacement updates DB first and then deletes old file. Output is not approved automatically; every successful render is `needs_review` with no approval fingerprint.

## Recorded render checks

Recorded 23 Oct 2026 on i3-9100F, 15.9 GiB RAM, RX 570 4 GiB, FFmpeg 9.0.2 Gyan build, with a 19.5 s CPU baseline and 37.5–37.8 s measured highlight renders. Results below are specific to this driver/build/settings.

| Case | Encoder | Encoder time | File size | Comparison |
|---|---|---:|---:|---|
| 720p Clean/Bold/Highlight | libx264 veryfast CRF 23 | 14.1–18.5 s | 10.5–11.5 MB | baseline |
| Equivalent 720p AMF probe | h264_amf VBR peak, 2.3 Mbps | 9.8 s | 11.5 MB | luma SSIM 0.9723 vs x264 |
| 1080p prior CPU highlight | libx264 veryfast CRF 23 | 31.4 s | 19.21 MB | baseline |
| 1080p final app highlight | h264_amf VBR peak, 4 Mbps | 18.6 s | 19.76 MB | 1.69× faster; luma SSIM 0.9805 |

AMF speed gain at 720p was modest with lower SSIM, so app keeps x264 there. At 1080p AMF was 1.69× faster in this run with a 2.8% larger file and visually similar inspected frame.

Recorded output QA used a saved 38.26 s candidate from a 25:45 local source; analysis/transcription were not rerun. Seven style/crop exports: all H.264/AAC, exact 9:16, complete FFmpeg decode, no detected black intervals, A/V duration delta 0.012–0.028 s and trim within 0.03 s of target. A/V quality check covered selected test clips, not arbitrary media. 1080p evidence covers the selected clip, not a broad range of input formats/content.

Quick Clip real and synthetic E2E measurements, including duration, CPU/RSS sampling, audio/no-audio output and source immutability, are in [Testing and Troubleshooting](testing-and-troubleshooting.md). Runs used 720p x264 and short intervals; GPU utilization was not sampled, and measurements are not a broad performance benchmark.

Mood Quotes synthetic FFmpeg E2E was recorded 24 Oct 2026 on the same Windows 11/i3-9100F/RX 570 workstation. All four 4-second 720p renders passed ffprobe: short looping synthetic video + background audio/music mix (0.67 s, 763,549 bytes), solid color + silent AAC (0.48 s, 17,498 bytes), PPM gradient + silent AAC (0.97 s, 29,707 bytes), and still image + silent AAC (0.78 s, 17,125 bytes). All were H.264/AAC 720×1280 at 30 FPS, with Unicode/ASS animation and no AI calls. These historical runs predate V2.4 offset/mute cases; new V2.4 synthetic cases remain unrun. These tiny synthetic renders validate the path, not real-content quality or longer/1080p performance.

## Storage and failure behavior

- `DATA_DIR` defaults to `%LOCALAPPDATA%\Klipnara`; `SOURCE_DIR`/`CLIP_DIR` can be separate roots. Shared images/audio use `SOURCE_DIR/library-assets`; legacy managed folders remain readable.
- Work files (transcription `.wav`/`.m4a`, `.ass`, logs) use data `work` directory. Subtitle audio is removed after transcription; provider upload cleanup is best-effort. Logs rotate `klipnara.log` at 2 MB with three backups.
- Path helpers only serve/delete files inside managed source, shared asset, Mood, and clip folders.
- `ffprobe`/FFmpeg binary errors return local errors. Ensure binaries are on `PATH` or set `FFPROBE_PATH`/`FFMPEG_PATH`. Source Clip 1080p uses x264 when AMF is absent, but a listed AMF encoder that fails at runtime has no automatic retry; check driver/build or choose 720p.

See [Getting Started](getting-started.md) for install and [Testing and Troubleshooting](testing-and-troubleshooting.md) for actual integration test command and known validation limits.
